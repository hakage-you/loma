# 提案の質を比べる手順

プロンプトやモデルを変えたときに、**前より良くなったのか**を決めるための手順。
何度も繰り返すので形を固めてある。

## 守ること

**1. 変数は1つずつ変える。**

2026-08-12 にこれを破って失敗した。qwen3:14b で採ったラベルを見てプロンプトを直したが、
出荷対象は gemma4:12b だった。ラベルに出た失敗8件のうち**7件を gemma4 は元から出しておらず**、
存在しない問題を潰そうとしていた。**対象モデルで同じ失敗が起きるかを先に確かめる。**

**2. 評価は必ず同じDBの写しで行う。**

タグIDと使用数が変わると比較にならない。`VACUUM INTO` で写しを作る
（`.db` だけコピーすると WAL の内容が抜ける）。実DBには書き込まない。

**3. 機械指標を質の根拠にしない。**

回収率・閾値・所要時間・提案数は、**出た提案のうち何割が正しいかを何も言わない**。
人手判定を通していないものは「未測定」と書く。

**4. 判定軸は「提案として出す価値があるか」。**

「同義・包括だと確定した」ではない。統合するかはユーザーが決められるので、
多少広くても価値があれば ○。「意味は近いが統合先として無意味」なら ×。

## 判定の台帳

`results/judgments.tsv` に**ペア単位**で貯める。

```
target<-member	good|bad|hold	method	YYYY-MM-DD
```

「`container ← lid` は提案として良いか」は**どのモデルが出したかに依らない**ので、
比較ごとに分けず1箇所に貯める。**2回目以降は未判定のぶんだけ聞かれる。**
同じ鍵が複数行あれば最後の行が有効（判定を変えられる）。

## 手順

### 1. 変更前の状態を写しに取る

```bash
node tools/db-snapshot.mjs            # 実DBの写し（アプリ起動中でも可）
```

比較用は scratchpad などに `VACUUM INTO` で作る。**プロンプトを変える前に取ること。**

### 2. 変更して、同じ写しで走らせる

プロンプトを変えたら `STAGE2_PROMPT_VERSION` を上げる。
版が違えば保存済みの判定を引き継がないので、条件の違う結果が混ざらない。

```bash
cd src-tauri
LOMA_BASELINE_DB='<写しのパス>' cargo test --release hypernym_on_real_data -- --ignored --nocapture
```

### 3. 差分だけ判定する

```bash
node tools/text-check/label-diff.mjs --before <前のdb> --after <後のdb> --method hypernym
```

共通して出るペアは比較に寄与しないので見ない。見るのは:

| | ○ だった | × だった |
|---|---|---|
| **消えたペア** | 退化（拾えていたものを落とした） | 改善（消して正解） |
| **増えたペア** | 改善 | 退化（ゴミが増えた） |

標本は各側30件が既定。seed 固定なので**同じ標本が再現できる**。

### 4. 結果を読む

```bash
node tools/text-check/label-diff.mjs --before <db> --after <db> --report
```

母集団への引き伸ばしは**標本比からの推定であって実数ではない**。
差引が小さいときは「互角」と読む（標本30件では±10件程度は誤差の範囲）。

## 適合率そのものを測るとき

比較ではなく「いまどのくらい正しいのか」を知りたいときは `label.mjs`。
層化抽出して層ごとの適合率を出す。

```bash
# 提案を書き出す（本番の組み立て経路を通す。JS 側に写しを持たない）
cd src-tauri
LOMA_BASELINE_DB='<db>' LOMA_LABEL_OUT='../tools/text-check/results/proposals.json' \
  cargo test --release dump_suggestions_for_labeling -- --ignored --nocapture

cd ..
node tools/text-check/label.mjs --method hypernym
node tools/text-check/label.mjs --method rules --report
```

層の切り方:

| 方式 | 層 | 何を判断したいか |
|---|---|---|
| ① 規則 | 当たった規則の組み合わせ | 「4規則なら信用できる」が言えるか |
| ② 包括関係 | グループの大きさ | 大きいグループほど混ざるか |
| ③ 関連タグ | 種別（basic / descriptive） | 種別ごとにモデルを分けた効果 |

**小標本の区間は広い。** n=12 の 58% は 95%区間で 32〜81% あり、
n=17 の 82%（59〜94%）と重なる。区間が重なっているうちは差を主張しない。
